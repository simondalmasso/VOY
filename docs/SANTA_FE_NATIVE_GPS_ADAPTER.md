# VOY — Santa Fe native GPS adapter (P0 public recovery)

## Runtime truth

The worker has a same-origin `GET /api/transit/santa-fe/vehicles` integration boundary.
No source is activated without maintainer approval. The default production response is:
`{"ok":true,"status":"not_integrated","source_id":null,"observations":[]}`.

The adapter implements the **verified Cuándo Pasa live-arrivals source** (see
`docs/SANTA_FE_CUANDOPASA_SOURCE.md` for endpoint evidence, schema and field mapping).
It only activates **after the maintainer explicitly confirms reuse rights and configures
the documented env bindings**. The live proof script executes the adapter against the
real source; do not treat a passing proof as authorization.

## Activation contract (Worker environment bindings, not browser config)

- `VOY_SF_GPS_REUSE_APPROVED=YES`: explicit maintainer approval **after** confirming contract and license.
- `VOY_SF_GPS_FEED_URL`: approved API **base root** (e.g. `https://api.cuandopasa.com.ar/`); no path, no user info, no query, no fragments. The adapter appends `/v0/stops/{x_stop_code}/arrivals?source=poll` itself.
- `VOY_SF_GPS_APPROVED_HOST`: exact approved host, must match the base URL.
- `VOY_SF_GPS_SOURCE_ID`: stable `sf_gps_...` identifier from the source registry review (e.g. `sf_gps_cuandopasa`).
- `VOY_SF_GPS_LICENSE_URL`: published written authorization/terms URL, HTTPS.

No authentication tokens or account credentials: the verified source is unauthenticated,
and the generic contract intentionally rejects authenticated URLs.

## Verified provider protocol (2026-10-16 evidence)

`GET {FEED}/v0/stops/{x_stop_code}/arrivals?source=poll` returns Spanish EFISAT-style JSON:

```json
{"CodigoEstado":0,"MensajeEstado":"ok","arribos":[
 {"DescripcionLinea":"9","DescripcionBandera":"AL POZO","Arribo":"5 min. aprox.",
  "Latitud":"-31.65173","Longitud":"-60.713448","LatitudParada":"-31.647121","LongitudParada":"-60.700868",
  "EsAdaptado":"True","IdentificadorCoche":"3228","IdentificadorChofer":"MARQUEZ H. (40089)",
  "DesvioHorario":"-02:21","UltimaFechaHoraGPS":"16/10/2026 17:33:49","MensajeError":"",
  "CodigoLineaParada":"75"}]}
```

Response headers carry the source's own freshness truth: `x-cache-source: fresh|cache|stale`
and `x-data-fetched-at` (ISO UTC of the source's upstream fetch). Stop codes (`x_stop_code`,
e.g. `704`) and line codes (`x_line_code`, e.g. `75` for línea 9 / route `SF09`) come from the
published static bundle `https://api.cuandopasa.app/data_v2`; VOY embeds the per-route stop
catalog as `src/sf-cuandopasa-stops.generated.js` (generated by
`scripts/generate-sf-cuandopasa-catalog.mjs`, bundle version pinned in file metadata).

Worker-side field mapping (evidence in `docs/SANTA_FE_CUANDOPASA_SOURCE.md`):

- vehicle id (pseudonymous): `{x_line_code}-{IdentificadorCoche}` — **driver identity (`IdentificadorChofer`) is never carried into VOY**.
- `route_id` = SF route id (`SF09`), `line` = short name (`9`), `trip_id` = `DescripcionBandera` (destination).
- `lat`/`lon` = `parseFloat(Latitud)`/`parseFloat(Longitud)` (bus position, not `LatitudParada`).
- `observed_at` = `UltimaFechaHoraGPS` parsed as `dd/MM/yyyy HH:mm:ss` in America/Argentina/Santa_Fe (UTC-3 fixed, no DST) → ISO UTC. Offset verified by temporal coherence against live polls.
- `delay_seconds` = `DesvioHorario` (`±HH:MM`) → signed seconds.
- Arrival gating: `CodigoEstado===0 && MensajeEstado==='ok'`; per-line filtering by `CodigoLineaParada`.

## Truth and budgets (evidence-revised 2026-10-16)

- Only WGS84 numeric positions inside bounded Santa Fe metro latitude [-31.95,-31.3], longitude [-61.08,-60.3].
- **Age window 90 s / future skew 5 s** (revised from the pre-evidence 20 s draft: measured GPS age at reception is 40–80 s with upstream refresh ~30–60 s; the source's own client tolerates 5 minutes — see `docs/SANTA_FE_CUANDOPASA_SOURCE.md §frecuencia`). Timestamps are never rewritten to appear fresh; stale observations are discarded, not downgraded.
- Upstream: ≤ 24 stop polls per request (parallel, ≤ 2.5 s total deadline), ≤ 160 kB per stop payload; per-line queries stride-sample ≤ 12 stops; citywide queries poll one rotating stop per route per minute.
- Max 16 current accepted vehicles, sorted freshest first; 5 s in-isolate cache keyed by source+line scope; 15 s browser poll (only while visible in local coverage).
- Failure yields `source_unavailable` (all stops failed); empty/expired yields `no_current_positions` (answered stops, zero fresh observations); partial stop failures deliver partial truth with `stops_answered < stops_queried` visible in the response.
- 2D/3D render the **observed GPS point only** (`observed_position_only`), without snapping/interpolation absent independently verified geometry.
- Browser stops polling entirely when the endpoint reports `not_integrated`. Worker responses are `cache-control:no-store`.
- Static published bus lines and the external Cuándo Pasa handoff remain separate.

## Line filter

`GET /api/transit/santa-fe/vehicles?line={short_name}` (e.g. `?line=9`, `?line=C`)
narrows polling to that line's stops and filters arrivals by line code. Unknown or
malformed lines fail closed (`source_unavailable` + `reason:"unknown_line"`) without
manufacturing anything. The browser line picker passes the selected short name.
